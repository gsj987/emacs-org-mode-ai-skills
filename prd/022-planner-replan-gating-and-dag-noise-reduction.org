#+TITLE: PRD 022 - Planner replan gating and DAG noise reduction
#+STARTUP: overview

* Problem
Planner execution currently issues a planner request after every executed step when =org-ai-skills-planner-auto-replan= is enabled. This causes excessive planning nodes in DAG output (for example planning.parse/request repeated after each step) and avoidable latency/cost, even when no replan signal exists.

* Scope
- In scope:
- Add explicit replan trigger policy for planner runs.
- Change default planner step-loop behavior to avoid intermediate replans unless trigger policy requests it.
- Preserve existing strict no-fallback planner parsing/execution contracts.
- Add ERT coverage for replan trigger gating behavior.
- Add BDD scenario documenting expected planner DAG behavior under reduced replanning.
- Update README planner configuration/behavior notes.
- Out of scope:
- Changing planner JSON schema contract.
- Changing execution skill behavior.
- Changing provider/tool-call integrations.

* Constraints
- Technical constraints:
- No fallback logic.
- Keep replan max-limit enforcement intact.
- Keep run-state/DAG observability compatible with existing fields.
- Process constraints:
- PRD-first implementation.
- Add tests in =tests/org-ai-skills-test.el= and =tests/bdd/=.

* Expected Behavior
- Behavior 1:
- Intermediate steps should not trigger planner re-requests when replan trigger policy does not require it.
- Behavior 2:
- Replan should still be possible at plan boundary (or when marker trigger appears), subject to =org-ai-skills-planner-max-replans=.
- Behavior 3:
- DAG output should show fewer redundant planning nodes for the same run.
