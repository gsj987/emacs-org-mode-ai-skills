#+TITLE: PRD 002 - First Skill Spec Implementation
#+STARTUP: overview

* Problem
当前项目尚未落地第一个可执行的 Skill Spec。
我们需要定义并实现一个最小但完整的 Skill 规范，让 Emacs 端可以发现、
解析、校验并在后续通过 gptel 调用它。

* Scope
本 PRD 聚焦 “第一个 Skill Spec 的最小闭环”：
- In scope:
  - 定义第一个 Skill 的 Org 结构规范（字段、语义标签、必填项）。
  - 在 =skills/= 添加第一个 Skill Spec 文件（作为规范样例与可加载对象）。
  - 在 =elisp/= 实现 Skill 发现、解析、基础校验能力（只覆盖首个 spec 所需）。
  - 实现与 =gptel= 的最小集成接口，能把解析后的 Skill 结构化数据传递给 gptel 请求层。
  - 在 =tests/= 添加 ERT 测试，覆盖成功与失败场景。
  - 在 ERT 中验证可加载 gptel，并验证结构化数据可被 gptel 集成层消费。
  - 更新 README 的使用说明（仅涉及首个 Skill Spec 的加载与验证）。
- Out of scope:
  - 通用 Planner 编排与多步任务执行引擎。
  - Run Ticket 的完整生命周期与复杂状态机。
  - 多 Skill 优先级、依赖图、自动重试等高级调度能力。
  - Proposal/Governance 自动审批流程。
  - 真实网络请求到远端模型服务（首版测试只验证本地结构与集成边界）。

*目标用户*
- Emacs 高级用户、技术写作者
- 需要可复用、可复盘、可组合的 AI 工作流
- 希望用 Org 文件驱动 AI 任务规划与执行

*核心价值*
- 结构化定义 AI 技能（Skill）
- 用自然语义标注行为约束（Effect、Invocation、Context）
- 分离技能定义（Spec）与状态（Run Tickets）
- Planner 模式：生成计划、调用子任务、追踪状态

*依赖*
- gptel: 提供与 LLM 的桥接与工具调用支持
- Org Mode: 文本结构与状态追踪
- 可选 Org Babel: 扩展执行环境

首版本地开发假设：
- gptel 源码位于 =~/.emacs.d/straight/repos/gptel/=
- 测试环境可通过 =add-to-list 'load-path= 加载 gptel

** 核心概念
*** Skill（技能）
一个 Org Mode 定义的可复用能力单元，用于扩展 agent 的行为。

特点：
- 由 Org 文件声明
- 包含元信息（软类型标签）
- 可被 Planner 自动发现并触发

*** Run Ticket（执行实例）
一次技能执行的状态记录，包括：

- 输入参数
- 生成的计划
- 子任务调用
- 输出与日志

*** Planner（规划者）
根据用户目标与上下文，调度 Skill 生成计划并追踪执行。

*** 软约束语义标签
每个 Skill 用自然语言标签声明其语义行为边界（类似类型注解），便于 agent 调度。

语义维度包括（可扩展）：

| 标签        | 含义                                         |
|-------------+----------------------------------------------|
| =EFFECT=      | 副作用等级（pure/local/external/irreversible） |
| =INVOCATION=  | 触发模式（auto/suggest/manual）                |
| =CONTEXT=     | 上下文范围（buffer/project/global）            |
| =DETERMINISM= | 确定性等级（deterministic/heuristic）          |

例如：

#+begin_example
,#+EFFECT: pure
,#+INVOCATION: suggest
,#+CONTEXT: project
,#+DETERMINISM: heuristic
#+end_example

agent 在调度前可以参考这些标签做决策

** Skill 定义约定（Org 格式）
首个 Skill 文件约定示例：

#+begin_example
,* Skill: Generate Structured Notes
:PROPERTIES:
:SKILL_ID: gen-notes
:END:

,#+EFFECT: pure
,#+INVOCATION: suggest
,#+CONTEXT: project
,#+DETERMINISM: deterministic

,** Description
将选中 Org 片段转换为结构化大纲。

,** When to Use
当需要将冗长文本抽象成段落/标题结构时。

,** Inputs
- org selection

,** Outputs
- structured org outline

,** Steps
1. Analyze Org text structure
2. Propose outline with TODOs
3. Return as Org subtree

,** Examples
- …

,** Notes
可在 Org Task 中自动触发
#+end_example

首个版本要求：
- 仅要求支持 =skills/= 目录中的 Org skill 文件发现。
- 不要求首版支持 =~/.emacs.d/skills/= 全局目录扫描。
- 必须能提取并返回：
  - =SKILL_ID=
  - 标题（Skill 名称）
  - Description 文本
  - 4 个语义标签（EFFECT/INVOCATION/CONTEXT/DETERMINISM）
- 必须提供一个面向 gptel 的结构化输出（建议 alist/plist），字段稳定且可测试。

* Constraints
- Technical constraints:
  - 保持 Skill Spec（只读定义）与运行态状态（Run Ticket）严格分离。
  - 运行时不得修改 =skills/= 中的 Skill Spec 文件。
  - Parser/Validator 输出应确定、可预测、可测试。
  - 错误必须显式返回（缺字段、标签非法、文件不可读等），禁止静默失败。
  - gptel 集成层不直接依赖交互式 buffer 状态；输入输出保持纯数据接口优先。
  - ERT 需显式处理 gptel 加载路径（=~/.emacs.d/straight/repos/gptel/=），并在缺失时给出明确失败信息。
- Process constraints:
  - 必须遵循 AGENTS.md 流程：PRD -> 实现 -> 测试 -> 测试执行 -> 文档 -> Worklog。
  - 所有实现与测试项必须可追踪到本 PRD 的任务列表。

* Expected Behavior
- Behavior 1: 当 =skills/= 存在合法首个 Skill Spec 时，系统可发现并成功解析。
- Behavior 2: 解析结果包含结构化字段：=skill-id=、标题、描述、语义标签。
- Behavior 3: 当缺失必填字段（如 =SKILL_ID=）时，返回明确错误信息。
- Behavior 4: 当语义标签值不在允许集合内时，返回校验失败。
- Behavior 5: 不发生对 Skill Spec 文件的写入或修改行为。
- Behavior 6: Skill 解析结果可转换为 gptel 可消费的结构化数据对象。
- Behavior 7: 在本地具备 gptel 代码时，相关 ERT 测试可在 batch 模式通过。

** 验收场景（首版）
1. 成功场景
   - 给定规范化 Skill 文件，调用加载接口返回非空 Skill 对象。
2. 缺字段场景
   - 删除 =SKILL_ID= 后加载，返回可断言的错误。
3. 非法标签场景
   - 将 =INVOCATION= 设置为非法值，返回可断言的错误。
4. 只读约束场景
   - 执行加载后，原 Skill 文件内容保持不变。
5. gptel 集成场景
   - 将 Skill 解析结果传入 gptel 集成函数，返回可断言的请求 payload 结构（无需真实发请求）。
6. gptel 加载场景
   - ERT 在设置 =~/.emacs.d/straight/repos/gptel/= 到 =load-path= 后可 =require 'gptel=。
