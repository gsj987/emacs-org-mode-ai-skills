#+TITLE: PRD 011 - Agentic Article Workflow Skills and Official Context Access
#+STARTUP: overview

* Problem
You want an agentic, human-in-the-loop workflow for article writing from Org drafts/discussion buffers:
1) summarize an outline from rough Org content,
2) human adjusts order and adds hints,
3) generate full article by outline,
4) regenerate selected subtree when needed,
5) run final editorial standardization.

Current system can rewrite subtrees, but article-specific workflow conventions are not explicit yet.

* Scope
- In scope:
  - Define article workflow skill architecture aligned with existing skill spec conventions.
  - Reuse existing fields (especially `:PURPOSE:`) instead of introducing redundant properties.
  - Add source-context contract (`source file path`) to support outline + generation stages.
  - Prioritize official context access tools (buffer/file read) for reliable agent execution.
- Out of scope:
  - Full UI redesign for drag-drop outline editing.
  - External publishing pipeline.

* Constraints
- Technical constraints:
  - Preserve spec vs run-state separation.
  - No runtime mutation of skill spec files under `skills/`.
  - Keep subtree targeting deterministic and bounded.
  - Prefer official framework tools/capabilities before custom ad-hoc tools.
- Process constraints:
  - Follow AGENTS workflow: PRD -> implementation -> tests -> test run -> README -> worklog.

* Expected Behavior
- Behavior 1:
  - Agent can produce a clean outline subtree from selected noisy Org draft/discussion content.
- Behavior 2:
  - Human can reorder/edit outline and set per-headline `:PURPOSE:` hints before generation.
- Behavior 3:
  - Agent generates article body from approved outline and source context.
- Behavior 4:
  - Agent can regenerate only designated subtree(s) without touching unaffected sections.
- Behavior 5:
  - Agent runs final editorial pass for wording consistency and tone/intonation alignment.
- Behavior 6:
  - Scope picker supports full-buffer target in addition to current/ancestor subtree scopes.

* Spec Design
** 1) Keep Existing Spec Conventions
Avoid new custom properties that duplicate semantics.

Decisions:
- Reuse `:PURPOSE:` for section intent/hint.
- Do not introduce `:ARTICLE_STATUS:`.
- Use Org filetags for state labels when needed (example: `:outline:`, `:draft:`, `:review:`).

** 2) Required Source Context Contract
Add explicit source-reference contract for article workflow.

Required runtime fields:
- `source_file_path`
  - Absolute or project-relative path to origin source document (Org/Markdown/text).
- `source_anchor` (optional but recommended)
  - Subtree id/headline path/marker-like selector for precise source scope.

Usage rules:
- Outline stage reads source via `source_file_path` (+ optional anchor).
- Generation/regeneration/editorial stages may re-read source for grounding and consistency.

** 3) Agentic Workflow (State-Driven, Human-Gated)
Model workflow as a loop with explicit stage intent, not rigid one-shot pipeline.

Agent stages:
- `discover`
  - Inspect source buffer/file and propose initial outline.
- `align` (human gate)
  - Human reorders headlines and edits `:PURPOSE:` per subtree.
- `compose`
  - Generate section drafts from outline + source context.
- `repair`
  - Regenerate selected weak subtree(s) only.
- `polish`
  - Run full editorial standardization pass.

Transition principle:
- Agent proposes next stage.
- Human confirms or overrides stage/target.
- Agent executes scoped action and records artifacts.

Scope selection rule:
- Reuse existing interactive scope picker.
- Add a `buffer` scope option so planner/rewrite flows can run on full buffer when needed.

** 4) Skill Architecture (Multiple Skills + Existing Planner Runtime)
Use multiple focused skills and rely on existing orchestration via =org-ai-skills-plan-run=.

Recommended skills:
- `article-outline-from-org`
  - Produce outline subtree, write `:PURPOSE:` stubs.
- `article-compose-from-outline`
  - Expand outline into section bodies.
- `article-repair-subtree`
  - Regenerate one selected subtree.
- `article-polish-editorial`
  - Normalize wording/tone across selected scope.


** 5) Official Context Access Priority
Most important requirement is dependable context access through official capabilities.

Priority order:
1. Buffer read capability (current working content, narrowed region/subtree)
2. File read capability (`source_file_path`)
3. Structured Org traversal helpers (headline/subtree selection)
4. Scoped write/apply for selected subtree/root

Implementation direction:
- First expose/standardize official file/buffer read tools in core framework.
- Reuse existing Org/runtime helpers where available.
- Introduce new Org-specific wrappers only when official capabilities cannot satisfy needs.

** 6) One Skill or Multiple Skills
Decision: multiple skills are preferred.

- Core authoring quality improves with stage-specialized prompts/contracts.
- Evaluation/testing is simpler per stage.
- Use existing planner-based execution (=org-ai-skills-plan-run=) to route stage actions.

* Acceptance Scenarios
1. Existing-field compatibility:
- Workflow uses `:PURPOSE:` and filetags; no `:ARTICLE_HINT:`, `:ARTICLE_INTENT:`, or `:ARTICLE_STATUS:` is required.

2. Source path grounding:
- Given `source_file_path`, outline and generation stages can read source content deterministically.

3. Human-gated stage transitions:
- After agent proposes outline, human can reorder/add `:PURPOSE:` hints and trigger compose stage.

4. Scoped repair:
- Regenerating one subtree does not modify sibling sections.

5. Editorial polish:
- Final pass improves consistency and tone while preserving structure and key meaning.
