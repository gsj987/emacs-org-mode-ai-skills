#+TITLE: org-ai-skills
#+STARTUP: overview

* Project Goal

org-ai-skills is an experimental Emacs system for defining, executing,
and evolving AI Skills using Org Mode and gptel.

The system treats Skills as structured cognitive procedures
that can be planned, executed, reviewed, and evolved safely.

This project aims to:

- Define a minimal Skill specification model
- Separate Skill spec from Run state
- Provide Planner + Run Ticket mechanism
- Enable controlled Skill self-evolution
- Use dev-agent-work style AI-driven development workflow

This is an experimental cognitive runtime for Emacs.

* Architecture Overview

Core concepts:
- Skill Spec (Org-defined, read-only)
- Run Ticket (execution instance)
- Proposal (change suggestion)
- Governance Gate (approval before commit)

System layers:

1. Skill Registry
2. Planner
3. Execution via gptel
4. Run Tracking
5. Proposal & Governance

* Directory Structure

- elisp/         → Emacs Lisp source code
- skills/        → Skill spec definitions

* Usage (Skill Spec v1)

** org-skill Spec (v1)

The first =org-skill= spec is file-based and validated with explicit rules.

Scope in v1:
- Discover only =*.org= files under =skills/=
- Parse one skill per file (top-level heading)
- Validate required fields and semantic tag values
- Return deterministic structured data for gptel integration

Required structure:
- Heading: =* Skill: <Skill Name>=
- Property drawer key: =:SKILL_ID: <id>=
- Required semantic tags:
  - =#+EFFECT:= one of =pure/local/external/irreversible=
  - =#+INVOCATION:= one of =auto/suggest/manual=
  - =#+CONTEXT:= one of =buffer/project/global=
  - =#+DETERMINISM:= one of =deterministic/heuristic=
- Required section: =** Description=

Minimal valid example:

#+begin_example
* Skill: Generate Structured Notes
:PROPERTIES:
:SKILL_ID: gen-notes
:END:

#+EFFECT: pure
#+INVOCATION: suggest
#+CONTEXT: project
#+DETERMINISM: deterministic

** Description
Transform selected Org content into a concise, structured outline.
#+end_example

Parse output contract (=org-ai-skills-parse-skill-file=):
- Returns plist keys:
  - =:file=
  - =:title=
  - =:skill-id=
  - =:description=
  - =:outputs= (list)
  - =:contracts= (list)
  - =:requirements= (list)
  - =:function-calls= (list of plists)
  - =:raw-sections= (plist)
  - =:tags= with nested plist:
    - =:effect=
    - =:invocation=
    - =:context=
    - =:determinism=

Failure behavior:
- Signals =org-ai-skills-parse-error= for:
  - Missing required fields/section
  - Invalid semantic tag values
  - Unreadable skill files
- Parser is read-only and does not modify files under =skills/=

gptel mapping contract (=org-ai-skills-build-gptel-payload=):
- Returns plist keys:
  - =:skill-id=
  - =:skill-title=
  - =:goal=
  - =:description=
  - =:tags=
  - =:prompt=

Load and inspect the first skill spec:

#+begin_example
(add-to-list 'load-path "/path/to/org-ai-skills/elisp")
(require 'org-ai-skills)

;; Discover skill files under skills/
(org-ai-skills-discover-skill-files)

;; Parse and validate one skill
(setq skill
      (org-ai-skills-parse-skill-file
       "/path/to/org-ai-skills/skills/001-generate-structured-notes.org"))
#+end_example

Build a structured payload for gptel:

#+begin_example
(org-ai-skills-build-gptel-payload
 skill
 "Draft a product specification for org-ai-skills plugin")
#+end_example

Load gptel from straight checkout path if needed:

#+begin_example
(org-ai-skills-require-gptel "~/.emacs.d/straight/repos/gptel/")
#+end_example

* Usage (Org Subtree Rewrite via gptel)

This feature rewrites an Org headline subtree with skill-guided prompting.

Interactive flow:
- Open any Org buffer.
- Place point in a target headline subtree.
- Run:
  - =M-x org-ai-skills-org-rewrite-subtree=
- Choose rewrite scope from minibuffer preview list (org-refile-like):
  - = [current] Top/Child/Leaf=
  - = [up:1] Top/Child=
  - = [up:2] Top=
- Choose a skill from =skills/=.
- Optional: add a custom rewrite instruction.

Core APIs:
- Resolve target subtree:
  - =(org-ai-skills-org-resolve-subtree 'current)=
  - =(org-ai-skills-org-resolve-subtree 'upper-level 1)=
- Build rewrite request payload:
  - =(org-ai-skills-build-gptel-rewrite-request skill subtree "Rewrite concisely")=
- Build normalized skill context bundle:
  - =(org-ai-skills-build-skill-context skill subtree)=
- Dispatch to gptel:
  - =(org-ai-skills-gptel-dispatch-rewrite request callback)=
- Install Embark action on Org headings:
  - =(org-ai-skills-embark-install-action)=

Failure behavior:
- Signals =org-ai-skills-org-context-error= for invalid Org context/ranges.
- Signals =org-ai-skills-gptel-error= if gptel is unavailable.

Output handling:
- Rewrite prompt enforces artifact-only output (no explanation/progress text).
- Response sanitizer strips leading chatter/code fences and normalizes heading levels
  so replacement root level always matches selected target subtree level.
- Rewrite request includes =:skill-context= with contracts/requirements/function-calls
  and source subtree metadata.

Debug observability:
- Toggle debug capture:
  - =M-x org-ai-skills-debug-toggle=
- Show last debug capture:
  - =M-x org-ai-skills-debug-show-last=
- Variables:
  - =org-ai-skills-debug-enabled=
  - =org-ai-skills-debug-buffer-name=
- Debug entry includes timestamp, buffer/file, target headline/path, final prompt,
  and full request plist passed to =gptel-request=.

Embark integration:
- Requires Embark installed.
- Registers action key =R= on target type =org-heading=.
- Trigger =R= from Embark on an Org heading target to run rewrite flow.

* Usage (Autonomous Planner + Lazy Skill Loading)

Planner mode adds automatic skill candidate selection, multi-step execution, and optional replanning.

Core model:
- Planner phase uses metadata-only skill index:
  - =org-ai-skills-load-skill-metadata=
- Execution phase lazy-loads full skill context only for selected step skills:
  - =org-ai-skills-load-skill-by-id=
- Planner command:
  - =M-x org-ai-skills-org-plan-and-run-subtree=
  - =M-x org-ai-skills-org-plan-and-run-subtree-repeat-task= (reuse previous planner task)
  - =M-x org-ai-skills-org-plan-and-run-subtree-preset= (select preset task intent)

Planner APIs:
- Build planner request:
  - =(org-ai-skills-build-planner-request task metadata run-state)=
- Parse planner response:
  - =(org-ai-skills-parse-planner-response response-text metadata)=
- Run task with planner orchestration:
  - =(org-ai-skills-run-task-with-planner task subtree)=

Balancing controls:
- =org-ai-skills-planner-max-steps= (default 6)
- =org-ai-skills-planner-max-replans= (default 2)
- =org-ai-skills-planner-auto-replan= (default t)
- =org-ai-skills-planner-max-skills-per-step= (default 2)
- =org-ai-skills-planner-batching-mode= (=quality-first=, =balanced=, =speed-first=)
- =org-ai-skills-planner-overflow-strategy= (=reject= or =split=)

Behavior notes:
- If planner returns too many skills in one step:
  - =reject=: signal planner validation error.
  - =split=: auto-split one oversized step into bounded step parts.
- Debug logging includes planner events, step composition reason, and per-step skill ids.
- Planner task reuse:
  - Last task is cached in =org-ai-skills--last-planner-task=.
  - Repeat command reruns planner on selected subtree with cached task.
  - If no prior task exists, repeat command signals a planner error.
- Embark keys on =org-heading=:
  - =R= manual single-skill rewrite
  - =P= planner run (prompt task)
  - =p= planner rerun with last task

Preset intents for common tasks:
#+begin_example
(setq org-ai-skills-planner-task-presets
      '(("meeting-notes" . "Rewrite into concise meeting notes with decisions and action items")
        ("rfc-brief" . "Rewrite into RFC format: Problem, Proposal, Risks, Open Questions")
        ("zh-polish" . "Polish wording and clarity; keep Chinese language and Org structure")))
#+end_example

Generate a keybind-friendly fixed-task command:
#+begin_example
(org-ai-skills-define-plan-run-preset-command
 org-ai-skills-plan-rfc-brief
 "Rewrite into RFC format: Problem, Proposal, Risks, Open Questions")

;; Example keybind
(global-set-key (kbd "C-c a r") #'org-ai-skills-plan-rfc-brief)
#+end_example
