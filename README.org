#+TITLE: org-ai-skills
#+STARTUP: overview

* Project Goal

org-ai-skills is an experimental Emacs system for defining, executing,
and evolving AI Skills using Org Mode and gptel.

The system treats Skills as structured cognitive procedures
that can be planned, executed, reviewed, and evolved safely.

This project aims to:

- Define a minimal Skill specification model
- Separate Skill spec from Run state
- Provide Planner + Run Ticket mechanism
- Enable controlled Skill self-evolution
- Use dev-agent-work style AI-driven development workflow

This is an experimental cognitive runtime for Emacs.

* Architecture Overview

Core concepts:
- Skill Spec (Org-defined, read-only)
- Run Ticket (execution instance)
- Proposal (change suggestion)
- Governance Gate (approval before commit)

System layers:

1. Skill Registry
2. Planner
3. Execution via gptel
4. Run Tracking
5. Proposal & Governance

* Usage (Skill Spec v1)

** org-skill Spec (v1)

The first =org-skill= spec is file-based and validated with explicit rules.

Scope in v1:
- Discover only =*.org= files under =skills/=
- Parse one skill per file (top-level heading)
- Validate required fields and semantic tag values
- Return deterministic structured data for gptel integration

Required structure:
- Heading: =* Skill: <Skill Name>=
- Property drawer key: =:SKILL_ID: <id>=
- Required semantic tags:
  - =#+EFFECT:= one of =pure/local/external/irreversible=
  - =#+INVOCATION:= one of =auto/suggest/manual=
  - =#+CONTEXT:= one of =buffer/project/global=
  - =#+DETERMINISM:= one of =deterministic/heuristic=
- Required section: =** Description=

Minimal valid example:

#+begin_example
* Skill: Generate Structured Notes
:PROPERTIES:
:SKILL_ID: gen-notes
:END:

#+EFFECT: pure
#+INVOCATION: suggest
#+CONTEXT: project
#+DETERMINISM: deterministic

** Description
Transform selected Org content into a concise, structured outline.
#+end_example

Parse output contract (=org-ai-skills-parse-skill-file=):
- Returns plist keys:
  - =:file=
  - =:title=
  - =:skill-id=
  - =:description=
  - =:outputs= (list)
  - =:contracts= (list)
  - =:requirements= (list)
  - =:function-calls= (list of plists)
  - =:function-definitions= (list of emacs-lisp source block strings)
  - =:raw-sections= (plist)
  - =:tags= with nested plist:
    - =:effect=
    - =:invocation=
    - =:context=
    - =:determinism=

Failure behavior:
- Signals =org-ai-skills-parse-error= for:
  - Missing required fields/section
  - Invalid semantic tag values
  - Unreadable skill files
- Parser is read-only and does not modify files under =skills/=

gptel mapping contract (=org-ai-skills-build-gptel-payload=):
- Returns plist keys:
  - =:skill-id=
  - =:skill-title=
  - =:goal=
  - =:description=
  - =:tags=
  - =:prompt=

Load and inspect the first skill spec:

#+begin_example
(add-to-list 'load-path "/path/to/org-ai-skills/elisp")
(require 'org-ai-skills)

;; Discover skill files under skills/
(org-ai-skills-discover-skill-files)

;; Parse and validate one skill
(setq skill
      (org-ai-skills-parse-skill-file
       "/path/to/org-ai-skills/skills/001-generate-structured-notes.org"))
#+end_example

Build a structured payload for gptel:

#+begin_example
(org-ai-skills-build-gptel-payload
 skill
 "Draft a product specification for org-ai-skills plugin")
#+end_example

Example skill set for composition testing:
- =skills/001-generate-structured-notes.org=
  - Expands and structures subtree content with richer detail.
- =skills/002-simplify-for-twitter-post.org=
  - Compresses subtree content into concise, tweet-ready wording
    (including <= 280 character tweet sentence constraint in contracts).
- =skills/003-daily-financial-news-report.org=
  - Uses Search1API-backed raw data function call; LLM formats final Org report.

Load gptel from straight checkout path if needed:

#+begin_example
(org-ai-skills-require-gptel "~/.emacs.d/straight/repos/gptel/")
#+end_example

* Usage (Org Subtree Rewrite via gptel)

This feature rewrites an Org headline subtree with skill-guided prompting.

Interactive flow:
- Open any Org buffer.
- Place point in a target headline subtree.
- Run:
  - =M-x org-ai-skills-org-rewrite-subtree=
- Choose rewrite scope from minibuffer preview list (org-refile-like):
  - = [current] Top/Child/Leaf=
  - = [up:1] Top/Child=
  - = [up:2] Top=
- Choose a skill from =skills/=.
- Optional: add a custom rewrite instruction.
- One command run generates one candidate output and stores it.
- Interactive runs auto-open a 2-column workspace:
  - left: =*org-ai-skills-control*= (run status + operation keys)
  - right: source Org buffer (target region overlay)
- Interactive runs auto-apply the newly generated candidate by default.
- Disable auto-apply if needed:
  - =(setq org-ai-skills-auto-apply-generated-candidate nil)=
  - Then select/apply manually from candidate list.
- Disable auto-open workspace if needed:
  - =(setq org-ai-skills-ui-auto-open nil)=
- Tune control-panel width (columns):
  - =(setq org-ai-skills-ui-control-window-width 34)=
  - Runtime also caps control width at half of current frame.

Control workspace keys (in =*org-ai-skills-control*=):
- =s=: stop current run (enabled only while status is =running=)
- =g=: rerun with same context (dispatches a new run; unavailable while running)
- =t=: adjust planner task / rewrite instruction, then rerun (unavailable while running)
- =c=: open minibuffer candidate selector
- =a=: apply currently selected candidate (unavailable while running)
- =d=: mark selected candidate as discarded (unavailable while running)
- =q=: close workspace (run continues in background; use =s= to stop)
- =r=: refresh control buffer

Control panel details:
- On first workspace activation, focus moves to control panel for key-driven operation.
- Key rows are highlighted when available and dimmed when unavailable.
- Candidate history list is rendered directly in control panel for long review flows.
  - Compact format: index + status + short preview (IDs/timestamps hidden in panel).

Candidate apply command:
- =M-x org-ai-skills-org-apply-slot-candidate=
- Select target scope, then pick one saved candidate from minibuffer.

Core APIs:
- Resolve target subtree:
  - =(org-ai-skills-org-resolve-subtree 'current)=
  - =(org-ai-skills-org-resolve-subtree 'upper-level 1)=
- Build rewrite request payload:
  - =(org-ai-skills-build-gptel-rewrite-request skill subtree "Rewrite concisely")=
- Build normalized skill context bundle:
  - =(org-ai-skills-build-skill-context skill subtree)=
- Dispatch to gptel:
  - =(org-ai-skills-gptel-dispatch-rewrite request callback)=
- Install Embark action on Org headings:
  - =(org-ai-skills-embark-install-action)=

Failure behavior:
- Signals =org-ai-skills-org-context-error= for invalid Org context/ranges.
- Signals =org-ai-skills-gptel-error= if gptel is unavailable.
- Signals =org-ai-skills-function-call-error= for invalid/missing skill function calls.

Output handling:
- Rewrite prompt enforces artifact-only output (no explanation/progress text).
- Response sanitizer strips leading chatter/code fences and normalizes heading levels
  so replacement root level always matches selected target subtree level.
- Rewrite request includes =:skill-context= with contracts/requirements/function-calls
  and source subtree metadata.
- Each run persists one candidate version under:
  - =~/.emacs.d/skills/versions/=
- Candidate store read/write uses UTF-8 by default.
- If headline =:ID:= is missing, runtime auto-generates and writes it back before candidate persistence.
- Overlay behavior:
  - running: highlight target region as processing
  - ready: mark pending replacement candidate
  - cleared on stop/apply/workspace close and immediately after candidate switch
- Function calls are skill-scoped runtime state:
  - Declared calls are available only while a skill is actively applied.
  - Excluding or finishing a skill unloads its function calls from request context.
  - Function implementations are loaded from skill-local Org code blocks
    (section =** Function Definitions=, =#+begin_src emacs-lisp ...=).

Function call lifecycle APIs:
- =(org-ai-skills-apply-skill-function-calls skill)=
- =(org-ai-skills-exclude-skill-function-calls skill-or-id)=
- =(org-ai-skills-active-skill-function-calls skill-or-id)=
- =(org-ai-skills-clear-active-skill-functions)=

gptel tool registration behavior:
- Active skill =Function Calls= are converted to request-scoped gptel tools.
- Per-argument hints can be declared in =Function Calls= (for example =query:=,
  =limit:=, =language_hint:=, =date:=) and are propagated to gptel tool arg
  descriptions.
- Planner still decides skill selection and step execution order.
- Runtime passes registered tools via =gptel-tools= and =gptel-use-tools= during
  each =gptel-request= dispatch.

Role-scoped model and system prompt routing:
- Planner requests use role =planner=.
- Rewrite and step-execution requests use role =execution=.
- Model overrides:
  - =org-ai-skills-model-planner=
  - =org-ai-skills-model-execution=
  - Set either to =nil= to use gptel default model selection.
- Planner generation stability controls:
  - =org-ai-skills-planner-temperature= (default =0.0=)
  - =org-ai-skills-planner-max-tokens= (default =2048=, or =nil= for backend default)
  - Planner requests also use gptel structured output schema (= :schema =)
    to enforce JSON shape at provider/backend level.
- System prompt overrides:
  - =org-ai-skills-system-prompt-planner=
  - =org-ai-skills-system-prompt-execution=
  - If set to empty string, runtime falls back to built-in default prompt for that role.
- Dispatch attaches role-specific =:system= prompt to each =gptel-request= call.
- Model routing is applied via dynamic =gptel-model= binding per request role.

Search1API credential lookup:
- API key is read from auth-source:
  - =(auth-source-pick-first-password :host "search1api")=
- Example =~/.authinfo= entry:
#+begin_example
machine search1api login apikey password YOUR_SEARCH1API_KEY
#+end_example

For the financial news example, Search1API functions are defined inside:
- =skills/003-daily-financial-news-report.org=

Debug observability:
- Toggle debug capture:
  - =M-x org-ai-skills-debug-toggle=
- Show last debug capture:
  - =M-x org-ai-skills-debug-show-last=
- Variables:
  - =org-ai-skills-debug-enabled=
  - =org-ai-skills-debug-buffer-name=
- Debug entry includes timestamp, request role, effective model, system prompt
  fingerprint, buffer/file, target headline/path, final prompt, and full request
  plist passed to =gptel-request=.
- Additional debug events:
  - =gptel-request-data= includes request payload data captured from gptel callback info.
  - =tool-call= and =tool-result= events are logged when gptel emits tool-calling callbacks.

Embark integration:
- Requires Embark installed.
- Registers action key =R= on target type =org-heading=.
- Trigger =R= from Embark on an Org heading target to run rewrite flow.

* Usage (Autonomous Planner + Lazy Skill Loading)

Planner mode adds automatic skill candidate selection, multi-step execution, and optional replanning.

Core model:
- Planner phase uses metadata-only skill index:
  - =org-ai-skills-load-skill-metadata=
- Execution phase lazy-loads full skill context only for selected step skills:
  - =org-ai-skills-load-skill-by-id=
- Planner command:
  - =M-x org-ai-skills-org-plan-and-run-subtree=
  - =M-x org-ai-skills-org-plan-and-run-subtree-repeat-task= (reuse previous planner task)
  - =M-x org-ai-skills-org-plan-and-run-subtree-preset= (select preset task intent)

Planner APIs:
- Build planner request:
  - =(org-ai-skills-build-planner-request task metadata run-state)=
- Parse planner response:
  - =(org-ai-skills-parse-planner-response response-text metadata)=
- Run task with planner orchestration:
  - =(org-ai-skills-run-task-with-planner task subtree)=

Balancing controls:
- =org-ai-skills-planner-max-steps= (default 6)
- =org-ai-skills-planner-max-replans= (default 2)
- =org-ai-skills-planner-auto-replan= (default t)
- =org-ai-skills-planner-max-skills-per-step= (default 2)
- =org-ai-skills-planner-batching-mode= (=quality-first=, =balanced=, =speed-first=)
- =org-ai-skills-planner-overflow-strategy= (=reject= or =split=)

Behavior notes:
- If planner returns too many skills in one step:
  - =reject=: signal planner validation error.
  - =split=: auto-split one oversized step into bounded step parts.
- Planner apply behavior:
  - Interactive planner commands (=org-ai-skills-org-plan-and-run-subtree=,
    =...-repeat-task=, =...-preset=, and fixed-task commands from
    =org-ai-skills-define-plan-run-preset-command=) auto-apply the newly
    generated candidate by default.
  - Set =(setq org-ai-skills-auto-apply-generated-candidate nil)= to require
    manual candidate selection/apply.
- Debug logging includes planner events, step composition reason, and per-step skill ids.
- Planner task reuse:
  - Last task is cached in =org-ai-skills--last-planner-task=.
  - Repeat command reruns planner on selected subtree with cached task.
  - If no prior task exists, repeat command signals a planner error.
- Embark keys on =org-heading=:
  - =R= manual single-skill rewrite
  - =P= planner run (prompt task)
  - =p= planner rerun with last task

Preset intents for common tasks:
#+begin_example
(setq org-ai-skills-planner-task-presets
      '(("meeting-notes" . "Rewrite into concise meeting notes with decisions and action items")
        ("rfc-brief" . "Rewrite into RFC format: Problem, Proposal, Risks, Open Questions")
        ("zh-polish" . "Polish wording and clarity; keep Chinese language and Org structure")))
#+end_example

Generate a keybind-friendly fixed-task command:
#+begin_example
(org-ai-skills-define-plan-run-preset-command
 org-ai-skills-plan-rfc-brief
 "Rewrite into RFC format: Problem, Proposal, Risks, Open Questions")

;; Example keybind
(global-set-key (kbd "C-c a r") #'org-ai-skills-plan-rfc-brief)
#+end_example
